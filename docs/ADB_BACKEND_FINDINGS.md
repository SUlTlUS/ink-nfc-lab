# 小米 17 / ST54L 的 ADB Shell 实验结论

本页是可公开的阶段性摘要，不包含原始手机日志、卡 UID 或完整设备配置快照。具体结果只适用于当前测试手机、系统版本和原厂驱动板，不自动外推到所有 ST 手机。

## 已证实

- ADB Shell（UID 2000）在已授权的本机环境里，可以读取原轮询配置、暂时加入 7-bit `0x7A` 条目、读回，并在结束时恢复原值并再次读回。这证明**配置事务**可行，不证明空口短帧已收到板端回应。
- 板子被唤醒后，ST 控制器向主机报告 ISO-DEP 与 MIFARE 两种候选协议。主机先激活 ISO-DEP，随后主动休眠并尝试选择 MIFARE；Android 在这个过程中没有交付可供 App 使用的 Tag，因此纯 Shell 探针没有发送 D1。
- 曾分别尝试 ST 的 `SKIP_MIFARE` 私有入口与 ReaderMode 时序调整。命令获得成功应答，但未改变本机实际的重选结果。不能把 API 状态成功写成免 Root 刷屏成功。
- 只读检查发现本机 RF Discover 映射本来就没有 MIFARE 项；问题位于主机侧候选协议选择，不适合猜测发送新的控制器映射命令。没有改系统分区、NFC 配置文件或固件。
- 在这台 ST54L 手机上复现 NXP 社区 App 的 QTag 实验时，API 返回成功但未见 `0x71` Q-Poll 寻卡条目、Tag 或 D1。它不否定该路线在 NXP 手机上可用，只说明**不能按 API 返回值跨厂商复用**。

## 尚未解决

需要找到无需修改 NFC 服务进程、又能保持 ISO-DEP 激活并交付 Tag 的可靠接口，才可能把 ST 路线做成完整免 Root 手机刷图。已知 UID、`SKIP_NDEF`、ReaderMode 的 NFC-A 技术掩码均不能代替这一步。现有已验证完整刷图仍使用小米 17 的 Root 兼容后端。

后续适配应按“权限 → 特殊寻卡 → ISO-DEP Tag → D1 → 全部图像包 → 刷新回执 → 实屏检查”逐级记录证据，并为每次私有配置留出可核验的恢复路径。
